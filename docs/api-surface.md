# warp-metal public API surface vs NVIDIA warp-lang

Generated by `tools/gen_api_surface.py` — warp-metal 0.1.0 vs golden warp-lang 1.19.0.

## Method

warp-metal vendors the warp-lang 1.19.0 frontend verbatim and swaps the
backend (MSL over Adjoint SSA, ObjC++/Metal runtime). The public Python
surface is therefore *the frontend's own surface*: the conformance
instrument (`tools/conform.py`, three-layer ratchet) walks every
`wp.*` symbol the frontend corpus references — **356 symbols** —
and compares presence + exact signature against a golden dump from real
warp-lang 1.19.0. Signature identity is necessary but not sufficient:
numeric behavior is pinned separately by the corpus layer (CPU golden vs
Metal, tolerance-asserted per kernel, ratchet-only-up) and the
trajectory layer (per-step body_q diff, drift cap 0.15).

## Semantic deltas that signatures cannot show

These are the places where warp-metal is *deliberately* not bit-identical
or cannot be, and what replaces the upstream behavior:

1. **fp64 kernel types fail loud.** Metal exposes no fp64 on Apple
   Silicon. `float64`/`vec3d`/`mat63`-class kernel types raise a named
   TranslationError at compile time (host-side numpy fp64 interop is
   unaffected — arrays convert on the boundary). Upstream silently runs
   them on CUDA. The one accepted exemption (B1): the steel tiled
   solver's friction-patch fp64 accumulation is shim-branch fp32
   (KEP-0001 decision ⑤).
2. **Adjoint / Tape is a Non-Goal.** `requires_grad=True` allocation,
   `wp.Tape`, grad/adjoint codegen raise a named RuntimeError (fail loud
   at the earliest adjoint surface). Setting `requires_grad = False` is
   the plain-inference path and works (warp_nn Parameter).
3. **`warp.fem` / `warp.sparse` / kamino** import fails loud (Non-Goal;
   not ported). Examples in those families are named EXEMPT in the
   Newton smoke matrix.
4. **`wp.Volume` / NanoVDB** not implemented (Non-Goal); `wp.HashGrid`
   device surface is a named gap (fails loud, blocks particle-model
   `builder.finalize()`); OptiX-class features have no Metal equivalent
   and are permanently cut.
5. **Numeric tolerance classes** (corpus layer, rtol 1e-5 / atol 1e-6
   baseline): atomics reorder summation (looser per-kernel tolerance),
   `wp.inverse`/cholesky-family carry fp32 rounding deltas,
   cancellation-knife-edge fixtures compare against Metal being
   *closer* to fp64 than the fp32 CPU golden. 46/0/4 corpus + 3/3
   trajectory rows are the pinned evidence (capture sub-mode adds 27
   bitwise-identical replay rows).
6. **Texture sampling** is host-staging only (`wp.texture_sample` MSL
   lowering absent — fails loud).
